# 流场残差 Transformer 与训练系统

## 1. 任务定义

网络不从零预测流场，而是在精确翼型 SDF 与无粘源面元基线之上学习黏性修正。模型输出为：

```text
[(ux-u0x)/u_lb, (uy-u0y)/u_lb, (p-p0)/u_lb²]
```

`p0=0.5*(u_lb²-|u0|²)`，并与 GT 压力一样在流体域采用零均值规约。SDF 使用
`clamp(sdf/chord,-1,1)`；实际 `Re_lattice`、`nu` 与 `u_lb` 作为额外工况条件。

SDF 的原始值由 NACA 折线到每个格子中心的精确最短欧氏距离生成：先按四位数公式
在前后缘余弦加密采样，绕四分之一弦点旋转攻角，再把格子中心换算到弦长归一坐标。
点投影到每条闭合折线段并将投影参数截断到 `[0,1]`，所有线段距离的最小值即距离；
even-odd 射线法判定的翼型内部取负，最后乘弦长恢复格子单位。AABB 只剔除绝不可能
位于多边形内部的点，不近似距离；CPU/CUDA 分块也只影响内存与速度。

默认 `128×256` 网格、255 个折线顶点的 CPU 基准中，20 组翼型优化前后逐点完全一致；
4 线程中位数由 `56.446 ms` 降至 `13.180 ms`（4.28×），14 线程由
`126.639 ms` 降至 `63.289 ms`（2.00×）。

## 2. 网络结构

- Patch Size 为 `8×8`，token 维度 384，默认 `128×256` 网格形成 512 个 token。
- 位置编码采用二维 RoPE：每个注意力头的一半维度旋转 Y 坐标，另一半旋转 X 坐标，
  仅作用于 Q/K，不向 token 叠加绝对位置向量；频率基数由 `model.rope_base` 控制。
- 12 个 Pre-RMSNorm Transformer Block；SDPA 为 6 头非因果全局注意力。
- FFN 为 `384→1536→SwiGLU(768)→384`。
- 24 个子层保存各自原始增量。第 `s` 个子层输入为此前所有增量的静态 Softmax
  加权和，不执行普通 `x+F(x)`。25 行因果 logits 以压缩下三角存储，共 325 个标量，
  全零初始化时每行是历史均匀平均。
- 最终特征经 RMSNorm 后进入三级 `×2` PixelShuffle，空间逐级恢复到原网格。
  每级局部 RMSNorm 只位于细化残差分支，双线性/PixelShuffle 主路径不经过它，
  因此不会形成三个 Norm 串联的唯一梯度通道。

## 3. 精度边界

- 原始输入、Patch Embedding、条件投影与二维 RoPE 三角函数、旋转运算使用 FP32；
  旋转后的 Q/K 转回 Transformer 主干精度再进入 SDPA。
- CUDA Transformer 主干使用 BF16；设备不支持 BF16 时回退 FP16。
- 深度路由 Softmax、完整三级解码器、场重建与全部物理损失使用 FP32。
- FP16 使用 GradScaler，BF16 不使用；CPU 冒烟关闭 autocast，全流程 FP32。
- CUDA 的 FP32 矩阵乘法默认使用 `high` 精度模式，在支持的 GPU 上启用 TF32
  Tensor Core；张量与输出仍为 FP32。该设置不作用于 CPU。

## 4. 梯度监测

每隔 `training.log_every` 个优化器更新，在 GradScaler 解缩放之后、梯度裁剪之前统计
梯度。`grad_global_norm` 是全局二范数；`grad_rms_min/median/max` 是各参数张量的逐元素
梯度 RMS 分布；`grad_small_ratio` 表示 RMS 不高于
`training.gradient_small_threshold` 的参数比例。此外记录零梯度比例、无梯度参数数目、
非有限梯度数目和实际裁剪缩放比例。指标同时输出到终端及独立的
`gradients.jsonl/csv`，不会改变已有损失日志的列结构。

## 5. 损失与翼面邻域侧重

总目标包括流体域 Huber 监督、一阶梯度监督、不可压散度、稳态 Navier–Stokes
动量残差，以及翼面无滑移、入口速度、出口零梯度、上下周期边界。差分模板不会跨越
固体，压力在损失前固定流体域零均值规约。物理项在训练前 10% 步数内线性升权。

日志中的 `data` 是模型输出与 GT 归一化残差之间的逐点 Huber Loss：速度/压力残差先
分别除以 `u_lb`/`u_lb²`，再除以训练集对应通道的 RMS。它仅在流体节点上对三个输出
通道求平均，不包含任何物理项。`total` 才是 `data`、残差梯度监督和经过 warmup 的
物理损失按配置权重相加后的反向传播目标。每个 epoch 的验证指标独立写入
`validation.jsonl/csv`。

微调时额外计算 `edge_data`：用缓存输入首通道的精确 SDF 乘弦长还原格子距离，只在
翼型外部流体节点且距翼面不超过 `loss.edge_band_cells` 的区域归约监督 Huber Loss。
原有 `data` 保持全流体域、不加权的语义；`edge_data` 以
`loss.edge_data_weight` 单独加入 `total`，因此训练曲线仍可直接比较全域数据误差。
默认常规训练将额外权重设为 0；`config/finetune.yaml` 使用 4 格子邻域和 0.25 权重，
属于温和侧重，不会用狭窄边界带完全主导全场拟合。

## 6. PowerShell 命令

原始 LMDB 永远只读；第一次训练前先生成独立缓存：

```powershell
.\.venv\Scripts\python.exe train\run.py --mode prepare
.\.venv\Scripts\python.exe train\run.py --mode train
.\.venv\Scripts\python.exe train\run.py --env config\finetune.yaml --mode finetune --checkpoint output\training\best.pt
.\.venv\Scripts\python.exe train\run.py --mode eval --checkpoint output\training\best.pt
.\.venv\Scripts\python.exe vis\run.py --training-curves
.\.venv\Scripts\python.exe vis\run.py --inference
.\.venv\Scripts\python.exe vis\run.py --inference output\training\best.pt
```

其中 `--training-curves` 命令读取 `metrics.jsonl`、可选的 `validation.jsonl` 与
`gradients.jsonl`，生成
`output/training/training_curves.png`。重复 step 保留最后一条，适配断点续训；平滑窗口
由 `vis.training_curve_smoothing` 控制，图中同时保留低透明度原始曲线以显示尖峰。

训练曲线实现也可直接作为模块或脚本启动，两种方式行为一致：

```powershell
.\.venv\Scripts\python.exe -m vis.training_curves.training_curves
.\.venv\Scripts\python.exe vis\training_curves\training_curves.py
```

两条 `--inference` 命令从训练缓存读取样本，分别以 `seed` 决定的随机初始化权重和
训练检查点执行
前向推理，在 `vis.out_dir/inference` 下生成 Baseline、Prediction、GT 与绝对误差四列
对比图。可追加 `--indices 12 34` 选择实际样本编号；不指定时使用缓存开头的
`evaluation.num_visualizations` 个样本。检查点模式会校验缓存指纹，防止错误数据尺度下
生成看似正常但语义无效的结果。只应加载可信来源的 PyTorch 检查点。

训练输出中的 `global_step` 是跨 epoch 累计的优化器更新次数，每执行一次
`optimizer.step()` 增加 1。`training.batch_size` 是一次前向/反向的 micro-batch；名义
有效批量为 `batch_size × gradient_accumulation`，epoch 尾部不足完整批量时可能更小。
当前日志中的训练 loss 是触发该次更新的最后一个 micro-batch 的未缩放损失，不是累积
窗口平均值；梯度本身则由整个累积窗口共同产生。epoch 从 0 开始计数。

CPU 最小冒烟使用正式 12 层结构，执行完整前后向、单样本过拟合、checkpoint 往返
和预测图渲染：

```powershell
.\.venv\Scripts\python.exe train\run.py --env config\train_smoke.yaml --mode smoke
```

正式训练的可调参数全部位于 `config/default.yaml`；环境差异使用覆盖 YAML，禁止在
实现文件中复制默认值。

`finetune` 只加载 checkpoint 中名称和形状都与当前模型兼容的模型参数，不恢复旧的
优化器、学习率调度器、epoch 或 global step，也不要求旧缓存指纹与当前缓存一致。
被跳过的缺失、额外或形状不一致参数会记录进新 checkpoint 的 `pretrained` 字段，
启动时同时打印参数覆盖率。微调结果默认写入 `output/fine-tuning`，不会覆盖预训练输出。
`config/finetune.yaml` 默认训练 20 epoch，学习率为 `2e-5`，最小学习率为 `5e-7`；
如需调整预算或侧重范围，应另建环境覆盖 YAML，不在实现文件中改值。
