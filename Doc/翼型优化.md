# NACA 翼型参数端到端优化

## 功能边界

优化器冻结训练好的流场 Transformer 和计算网格，只更新 NACA 四位数族的连续参数
`m`（最大弯度）、`p`（弯度位置）与 `t`（最大厚度）。每项可分别设置数值边界、
初值与 `fixed`。固定工况由 `optimization.flow` 指定：

- `u_lb`：格子速度，不是 m/s；应位于训练数据实际速度覆盖范围内。
- `reynolds`：实际格子雷诺数，程序据此计算 `nu=u_lb*chord/Re`。
- `aoa_deg`：固定攻角。

端到端梯度链为 `NACA 参数 → SDF/面元基线 → Transformer 预测流场 → 翼面积分
Cl/Cd → 目标函数`。布尔固体掩码只负责模型物理边界，优化对象不是网格节点。

## 配置

所有选项位于 `config/default.yaml` 的 `optimization` 段。正式实验建议创建只覆盖所需
叶子的环境 YAML，例如 `config/my_optimize.yaml`：

```yaml
optimization:
  checkpoint: output/training/best.pt
  steps: 300
  flow:
    u_lb: 0.12
    reynolds: 350.0
    aoa_deg: 5.0
  parameters:
    naca_m:
      bounds: [0.00, 0.05]
      initial: 0.02
      fixed: false
    naca_p:
      bounds: [0.30, 0.50]
      initial: 0.40
      fixed: true
    naca_t:
      bounds: [0.10, 0.16]
      initial: 0.12
      fixed: false
  objective:
    mode: target_lift_min_drag
    target_lift: 0.6
    minimum_lift: 0.01
    lift_constraint_weight: 10.0
    lift_weight: 1.0
    drag_weight: 0.1
```

`objective.mode` 支持：

- `maximize_lift`：最大化升力系数。
- `minimize_drag`：最小化阻力系数的平滑绝对值。
- `maximize_lift_to_drag`：最大化 `Cl/(|Cd|+稳定项)`。
- `target_lift_min_drag`：逼近目标升力，同时降低阻力。

## PowerShell 命令

```powershell
.\.venv\Scripts\python.exe train\run.py --env config\my_optimize.yaml --mode optimize
```

也可只在命令行替换 checkpoint 路径：

```powershell
.\.venv\Scripts\python.exe train\run.py --env config\my_optimize.yaml --mode optimize `
  --checkpoint output\training\best.pt
```

结果写入 `optimization.output_dir`：`history.csv` 保存每一步参数与升阻，`result.json`
保存固定工况和全程最优结果。checkpoint 必须与 `training_data.cache_path` 的缓存指纹
一致；参数范围和工况超出训练覆盖时，结果属于代理模型外推，不应视作 CFD 验证。

## 使用 LBM 复核优化结果

优化日志只证明代理模型目标发生变化，不能单独证明真实 LBM 气动性能改善。复核程序会
从 `result.json` 读取初始参数、全程最优参数和固定工况，把两个翼型放在同一 LBM 批次中，
复用数据采集的粗细网格、势流初值、边界格式和严格稳态判据，然后用与代理优化完全相同
的表面积分公式重新计算 `Cl/Cd/objective`。

复核默认的优化结果：

```powershell
.\.venv\Scripts\python.exe vis\run.py --env config\my_optimize.yaml --optimization-lbm
```

或显式指定其他 `result.json`：

```powershell
.\.venv\Scripts\python.exe vis\run.py --env config\my_optimize.yaml `
  --optimization-lbm output\optimization\result.json
```

必须使用与优化/训练相同的网格及求解配置。结果写入 `vis.out_dir/optimization_lbm`：

- `lbm_comparison.png`：初始/最优翼型的同色标流场对比。
- `lbm_report.json`：收敛步数、实际格子工况、升阻与目标改善判定。
- `lbm_fields.npz`：两个案例的 `rho/ux/uy/p/mask` 原始数组。

所有目标模式都要求 `Cl >= optimization.objective.minimum_lift`。优化阶段会给违反该约束的
候选加入连续罚项，但硬判定不以罚项大小代替：只有找到正升力候选，`result.json` 的
`positive_lift_feasible` 才为 `true`；否则 `best` 仅保存最高升力的不可行候选，供诊断使用。

SDF 的前向仍严格采用 `sqrt(dist²)`，所以几何、训练缓存和 LBM 输入值不变；优化反向在
零距离附近使用由 `airfoil.sdf_backward_epsilon` 控制的平滑代理导数，避免网格中心恰落在
翼型边界时产生 `0×Inf=NaN`。反向结束后还会逐项检查 NACA 参数梯度，非有限梯度不会进入
裁剪器或 Adam 状态。

LBM 复核必须同时满足 `both_converged=true`、`lbm_positive_lift_feasible=true` 和
`lbm_objective_improved=true`，才能说 LBM 在配置目标下确认了有效改善。任一条件不满足，
尤其是优化翼型仍为负升力时，程序都会明确报告结果无效。
